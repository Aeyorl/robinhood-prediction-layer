# Deployment

## Local

```bash
pnpm install
pnpm dev:infra                       # docker compose: postgres + redis (optional)
pnpm contracts:local                 # anvil + DeployLocal.s.sol (mocks + example markets)
pnpm db:migrate
pnpm seed                            # loads deployments/local.json into postgres
pnpm dev                             # web (3000) + api (3001) + worker
```

Local demo data is generated by mock contracts and is clearly local/test data — never masquerades as live mainnet data.

## Testnet

1. Point env files at chain `46630` (`CHAIN_ID=46630`, testnet RPCs).
2. There is **no official testnet USDG** — never invent one. Deploy `MockUSDG` for testnet/local until an official address is configured.
3. Deploy the protocol core with `Deploy.s.sol` (`OWNER`, `FEE_RECIPIENT`, `CHAIN_ID`), configure feeds via `OracleRegistry`, create markets via `MarketFactory`.

## Mainnet (gated, chain 4663)

- Triggered only through `.github/workflows/deploy-mainnet.yml`, which requires explicit approval on a protected `mainnet` environment and re-runs the full contract test suite before deploying.
- The workflow runs `pnpm mainnet:preflight` before broadcasting. It verifies chain ID, bytecode at every external dependency, exact canonical addresses, the approved Safe owner set and threshold, and both signed-review flags. It sends no transaction during preflight.
- Configure the protected `mainnet` GitHub environment with required reviewers, then add:
  - secrets: `PRODUCTION_RPC_URL`, `DEPLOYER_PRIVATE_KEY`, `EXPECTED_SAFE_OWNERS`
  - variables: `MAINNET_EXTERNAL_AUDIT_APPROVED`, `MAINNET_COMPLIANCE_APPROVED`, `SAFE_ADDRESS`, `EXPECTED_SAFE_THRESHOLD`, `DEPLOYER_ADDRESS`, `FEE_RECIPIENT`, `USDG_ADDRESS`, `WETH_ADDRESS`, `SWAP_TARGET`, `DATA_STREAMS_VERIFIER`
- `EXPECTED_SAFE_OWNERS` is a comma-separated list stored as a secret. Approval flags may be set to `true` only when the signed evidence named in `docs/production-gates.md` is attached and accepted.
- The manual trigger requires the exact confirmation phrase `DEPLOY TO ROBINHOOD MAINNET 4663`. The workflow derives the sender from `DEPLOYER_PRIVATE_KEY` and requires it to match `DEPLOYER_ADDRESS` before broadcasting.
- `.github/workflows/container-images.yml` builds immutable API, worker and migration images from the same commit and publishes commit-SHA tags to GHCR and the production ECR repositories. Production services deploy that exact SHA tag.
- Run the migration image as a one-off task against the production database before starting the API and worker images. The API health endpoint must pass before the Vercel `NEXT_PUBLIC_API_URL` is changed.
- AWS resources are declared in `infrastructure/aws`. The `prediction-layer-production-foundation` stack owns the isolated ECS/ECR/IAM foundation; the `prediction-layer-production-data` stack owns private PostgreSQL, encrypted Redis, connection secrets, and its application security group; and the `prediction-layer-production-monitoring` stack owns the data-service dashboard, alarms and SNS alert topic. Keep the ECS services at zero desired tasks until every mainnet production gate and required runtime secret is present.
- Subscribe and confirm the approved on-call destination on `prediction-layer-production-alerts` before enabling traffic. An SNS topic with no confirmed subscription does not satisfy the monitoring gate.
- The `prediction-layer-production-migration` stack pins the one-off migration task to an immutable commit-SHA image. Run it in the application security group before enabling either long-running service, then require a zero exit code and retain its CloudWatch log stream as deployment evidence.
- The `infrastructure/aws/runtime.yml` template registers the gated API and worker task definitions. Both read the dedicated HTTP/WebSocket endpoint fields from `prediction-layer/production/rpc-endpoints`. Deploy this template only after the audited router/factory addresses, deployment block and signed approval flags are available; registering or starting it early would either embed unverified addresses or fail the API's production gate.
- Before any mainnet deployment, verify against official docs (see links in the repo README):
  - USDG: `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`
  - WETH: `0x0Bd7D308f8E1639FAb988df18A8011f41EAcAD73`
  - Uniswap Universal Router (chain 4663): currently documented `0x8876789976decbfcbbbe364623c63652db8c0904`
  - Data Streams verifier: currently documented `0xcE73c8ad08CBDEaCa6078BF0627C8fe0a9a536E7`
  - Curated Stock Token/feed pairs in `packages/chain-config/src/oracles.ts` against both Robinhood `/rhj/assets` and Chainlink's Robinhood reference-data directory.
- Configure Stock Tokens through `OracleRegistry.setStockTokenAssetConfig`, using the token itself as `oraclePauseToken`. Do not create a market until `resolver.health(assetKey).healthy` is true and the returned config hash is nonzero.
- No official Robinhood Chain sequencer uptime feed is listed as of September 5, 2026. Leave it zero until an official address is published and independently verified; the resolver uses Chainlink's `0 = up`, `1 = down` semantics when configured.
- Required reviews before launch: contract audit + remediation, compliance/legal review, multisig/timelock ownership, production RPC and observability, load testing, final brand review (see `08_ROADMAP.md` Phases 8–9).

## Address book

All addresses are config-driven in `packages/chain-config/src/addresses.ts`. After deploying, update `marketFactory`, `oracleRegistry`, `chainlinkPriceResolver`, `feeVault`, and `deploymentBlock` for the relevant chain — the worker's backfill start uses `deploymentBlock`.
